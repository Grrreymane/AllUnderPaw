## 改动与验证

1. 修改对应源码文件，保留结尾换行。
2. 执行 `npm run sync`。它先检查全部源文件与边界，检查失败不会写入发布文件。
3. 如果改了游戏文字，运行 `python D:/Minigame/_workflow/tools/subset_font.py .` 更新字体；本次纯搬移不需要重新生成字体。
4. 执行 `npm test`。界面、交互、资源或启动路径有变化时，再执行 `npm run test:browser`。
5. 一并提交源码和同步后的 HTML。图片放入 `art/`，测试输出保留在已忽略的 `.test-output/`，不要提交 `.cache/` 中的服务响应和临时文件。

新增模块必须在 `src/modules.json` 和 HTML 对应位置同时添加成对边界，顺序保持一致。所有 `src/` 下的 `.js` 都需要登记；嵌套边界、重复模块、缺少文件、漏登记文件和未同步内容都会导致检查失败。系统钩子和顶层代码对顺序敏感，不能按字母排序清单或直接改成异步加载。

剧本生成仍使用原来的 `tools/build-scenarios.js` 和 `src/scenario-presets.js`。它是离线前史维护步骤，本轮没有重跑或更改预设。存档格式、键名及迁移规则也没有变化。
